# PDFMarkup Ver1.51 仕様書

- Version：1.51
- 対象：PDFMarkup
- 作成日：2026-09-09
- 状態：完成
- 位置づけ：Ver1.5無料公開後の実利用改善版

---

# 1. 目的

PDFMarkup Ver1.51は、Ver1.5を実際に使用した際に見つかった不便や、利用者から寄せられた改善要望を反映し、日常的なPDF図面チェックをより使いやすくすることを目的とする。

Ver1.51では、新しい大型機能を増やすことよりも、図面を細かく確認しやすくすること、直線を意図した角度で描きやすくすること、複数の注釈をまとめて扱いやすくすること、複数PDFを同時に使う際の設定操作を減らすこと、PDFを開くまでの操作を減らすこと、チェック色の使い分けを増やすことを優先する。

Ver1.5で確立した基本操作・保存方式・PDF互換性をできるだけ維持し、大規模な構造変更は行わない。

---

# 2. Ver1.51の基本方針

Ver1.51は、

> **Ver1.5を実際に使って見えた不便を改善するVersion**

として扱う。

基本判断は以下とする。

```text
Ver1.51で日常的に使いやすくなるか
        ↓
Yes → 実装候補

将来必要だが、今入れると大きな変更になるか
        ↓
Yes → 将来仕様として残し、Ver1.51では無理に実装しない
```

ただし、将来予定している機能を実現しにくくする構造変更は避ける。

> **「今は実装しない」と「将来不要」は分けて考える。**

# 3. Ver1.51で実装する機能

## 3.1 PDF最大拡大倍率の拡張

### 目的
図面の細かい箇所を確認し、クリック・描画位置を指定しやすくする。

### 背景
Ver1.5利用者から、細かい箇所をクリックして指定したいため、現在よりさらに拡大できるようにしてほしいという改善要望があった。

### 仕様
- 最大ズーム倍率を1000%とする。
- 拡大後もパン操作を使用できる。
- 高倍率でも描画座標とPDF座標がずれないことを確認する。
- PDF表示が極端に粗くならないか確認する。
- 必要に応じて高倍率時のPDF描画解像度も検討する。

---

## 3.2 Shift直線の角度設定改善

### 現在
Shiftキーを押しながら描画すると直線になる。現在は特定角度付近で角度吸着が働くため、40°程度などの微妙な角度で描きたい場合に近い基準角度へ補正されることがある。

### 目的
直線化と角度吸着を分け、自由角度の直線と角度固定の両方を使用できるようにする。

### 基本操作

```text
Shift
→ 直線

Shift + Ctrl
→ 矢印
```

既存のショートカットは維持する。

### 角度吸着設定
基本設定として以下を持たせる。

- 角度吸着 ON / OFF
- 刻み角度
- 刻み角度の選択
- 刻み角度の直接入力

角度吸着OFFではShift直線とShift+Ctrl矢印を自由角度とする。ONでは設定した刻み角度の近くへ来た場合だけ吸着し、常に最寄り角度へ固定しない。

初期値は角度吸着ON、刻み角度45°とし、45°ではVer1.5の吸着許容幅±7.5°を維持する。狭い刻み角度でも全角度が強制吸着にならないよう、許容幅は刻み角度の1/4を上限とする。

上部ツールバーに黒い枠とチェック記号を明示した視認しやすいチェックボックスと編集可能なComboBoxを配置し、F9でもON/OFFを切り替えられるようにする。F9とチェックボックスの状態は即時同期する。

チェック側の表示切替ボタン以降は、`角度・チェックボックス・刻み角度・A・文字サイズ・選択・消しゴム・手` の順に配置する。「文字サイズ」という追加ラベルは表示しない。

よく使う刻み角度を候補として用意しつつ、必要な場合は数値を直接変更できるようにする。

例：

```text
15
30
45
90
```

直接入力は1°以上90°以下、小数点以下2桁までとし、22.5、37.25等を入力できる。負数や不正値ではアプリを終了させず、直前の有効値へ戻す。表示では不要な末尾0を付けない。

角度吸着OFFでも刻み角度を保持し、再度ONにしたとき前回値を使用する。角度吸着ON/OFFと刻み角度は既存の `settings.json` に保存し、次回起動時に復元する。

---

## 3.3 囲み複数選択

### 目的
複数の注釈・描画をまとめて選択し、一括操作できるようにする。

### 基本操作

```text
ドラッグで囲む
→ 複数選択

通常クリック
→ 単独選択

Shift + クリック
→ 選択追加 / 選択解除
```

AutoCADと同様に、ドラッグ開始点と終了点のX方向で選択方式を切り替える。上下方向は判定に使用しない。

```text
左 → 右
→ 完全に枠内へ入ったものだけ選択

右 → 左
→ 枠へ触れたものも選択
```

囲み選択した線注釈・文字注釈はDeleteでまとめて削除できる。線と文字が混在する場合も対象とし、一括削除は1回の操作としてUndo / Redoする。

---

## 3.4 選択した注釈の口径一括変更

複数選択した注釈に対し、口径を一括変更できるようにする。

例：

```text
選択中 8件
φ150
 ↓
φ100
```

### 変更対象
- PDFMarkup上の注釈情報
- PDFへ保存するコメント情報
- 画面上の表示情報
- 色等が口径設定と連動している場合は必要な関連情報

### Undo / Redo
線注釈・文字注釈が混在する場合も含め、選択中の全注釈へ一括反映する。一括変更は1回の操作としてUndo / Redoする。

## 3.5 PDFドラッグ＆ドロップ読み込み

### 目的
Windowsの既定PDFアプリをAcrobat等のまま維持しながら、PDFMarkupで簡単にPDFを開けるようにする。

### 対応

#### PDFMarkup画面へのドロップ

```text
Explorer
 ↓
PDFをPDFMarkup画面へドロップ
 ↓
PDFを開く
```

PDF以外は受け付けない。現在ウィンドウが空ならそのウィンドウで開き、別PDFを表示中なら既存の複数ウィンドウ方針に従って新しいウィンドウで開く。同じPDFが既に開いている場合は、そのウィンドウを前面へ表示する。

#### アプリ / ショートカットへのドロップ
PDFMarkup.exeまたはショートカットへPDFをドロップした場合は、起動引数からPDFを読み込む。

PDFMarkupを既定PDFアプリに設定することは前提としない。

## 3.6 左下ファイルパス表示の削除

現在画面左下に表示しているPDFのフルパスを非表示にする。

内部では、上書き保存、名前を付けて保存、ファイル管理、最近使ったPDF等に必要なパス情報を従来どおり保持する。画面表示のみ削除する。

### 目的
- 画面を簡潔にする。
- 説明記事・スクリーンショットにPC内のユーザー名やフォルダ構成が映り込むことを避ける。

## 3.7 チェック色の追加・既存色の調整

チェック用の色を、図面上で区別しやすい次の16色に整理する。

```text
黄         #FFE000
赤         #E53935
青         #1565C0
緑         #2E7D32
オレンジ   #FB8C00
紫         #8E24AA
ピンク     #EC407A
水色       #42A5F5
黄緑       #9CCC65
茶         #795548
シアン     #00ACC1
ターコイズ #00897B
ライム     #C0CA33
コーラル   #FF7043
インディゴ #3949AB
オリーブ   #827717
```

グレー・マゼンタ・ゴールドはチェック色へ表示しない。既存PDFの色情報を失わないため、グレーとマゼンタの内部読込互換は維持する。

朱書きは赤 `#C62828`、青 `#1565C0`、緑 `#2E7D32` の3色とする。チェック赤と朱書き赤は別の色として扱う。

色ボタン・画面描画・PDF保存は共通のRGB定義を使用し、表示色と実際の注釈色を一致させる。透明度・線幅の既存設定は変更しない。

### 確認する背景
- 白背景
- モノクロ図面
- カラー図面
- スキャン図面

24色化は将来候補とする。

## 3.8 描画設定の扱い

### 基本方針
Ver1.51のUI上では、

```text
朱書き
├─ 色
├─ 太さ
└─ 透明度

チェック
├─ 色
├─ 太さ
└─ 透明度
```

という考え方を基本とする。

色ごとに太さ・透明度を固定する方式は基本としない。

理由は、同じ赤色でも「赤い朱書き」「赤いチェック」のように、用途によって太さ・透明度を変えたい可能性があるため。

### 将来を考えた内部設計
将来の拡張を妨げないよう、内部では描画設定をPresetとして扱える構造を維持・検討する。

概念例：

```text
DrawingPreset
├─ Mode
├─ Color
├─ Thickness
├─ Opacity
└─ その他必要な描画設定
```

Ver1.51ではUI上は朱書き / チェック単位で設定してもよい。

将来、色・用途別Preset、ユーザー独自Preset、業務別Presetへ拡張できる余地を残す。

---

## 3.9 複数ウィンドウ間の描画設定同期

### 目的
複数のPDFを同時に表示しながらチェックする場合、同じ描画設定を各ウィンドウで設定し直す手間を減らす。

### 基本仕様
各ウィンドウには従来どおり描画設定UIを表示する。同一アプリプロセス内では新規描画用の設定変更を即時反映する。別プロセス間では既存の `settings.json` を使用し、新規起動時、ウィンドウがアクティブになった時、描画開始直前に最新設定を読み込む。

### 同期対象
- 朱書き / チェック等の描画モード
- 色
- 太さ
- 透明度
- 口径

選択中の既存注釈に対する編集操作は同期しない。

### 同期しないもの
以下はPDFウィンドウごとに独立させる。

- 現在ページ
- ズーム倍率
- パン位置
- 選択状態
- Undo / Redo
- PDF内の既存注釈
- 保存状態

同期するのは基本的に「これから描くものの設定」とする。

---

## 3.10 ウィンドウ単位の描画設定同期解除

各PDFウィンドウで、

```text
描画設定を同期
ON / OFF
```

を切り替えられるようにする。

チェックボックスは右側パネルの「現在のモード」表示行の右側へ `同期` として配置し、初期値はONとする。

### ON
共通描画設定を使用する。

### OFF
そのウィンドウだけ独立した描画設定を使用する。設定変更を他のウィンドウや `settings.json` へ送らず、他のウィンドウによる変更も取り込まない。

### 再度ON
`settings.json` に保存されている現在の共通描画設定へ即時に合わせる。

# 4. Ver1.51で追加した注釈機能

## 4.1 Ctrlまとめ書き

### 現在の問題
フリーハンドで文字等を書くと、ペンを離すたびに別のPDF注釈として保存される。

そのため、Acrobat等でコメント一覧を表示した際に、1画ごとにコメントが大量に並び、見づらくなる。

### 確定仕様
- 通常のフリーハンドは従来どおり、1 Strokeを1つのPDF Ink注釈として扱う。
- Ctrlだけを押した状態でフリーハンドを開始すると、Ctrlを離すまでに描いた複数Strokeを1つのInk注釈へまとめる。
- 左Ctrl・右Ctrlは同じ動作とし、Ctrlを押しただけでは注釈を作らない。
- 描画途中でCtrlを離した場合は、そのStrokeのMouseUp後にグループを確定する。
- Ctrlまとめ書きは1回のUndo / Redoで全Strokeを取り消し・復元する。
- Shiftは直線、Shift+Ctrlは矢印を優先し、Ctrlまとめ書きへ含めない。
- Ctrl+Z、Ctrl+P等の既存ショートカット実行だけではまとめ書きを開始しない。
- 同じInk注釈に属する各Strokeは共通IDで管理し、選択時は1注釈単位で扱う。
- PDF保存時は1つの `/Ink` 注釈の `/InkList` に複数のstroke arrayを格納する。
- PDF再読込時は同じ `/InkList` 内のstroke arrayへ共通IDを割り当て、再保存時も1注釈構造を維持する。
- UIの追加、自動時間判定、自動距離判定、文字認識は行わない。

# 6. 将来目標

PDFMarkupは、単なるPDF朱書きソフトで終わらせることを目的としていない。

最終的には、

> **PDF図面チェックアプリの基盤**

として育てる。

## 6.1 PDF比較
複数PDFを並べ、新旧図面比較、修正前後比較、ページ対応、差分確認等へ発展させる。

現在の複数ウィンドウ機能や描画設定同期は、この方向へつなげられる構造を意識する。

## 6.2 ページグループ / 束
複数ページを紙の束のように管理し、平面図・縦断図・詳細図・数量図等をグループ化して、次へ・前へ・ショートカット切替・ペンタブ画面への表示切替等へ発展させる。

## 6.3 複数モニター / ペンタブ対応
将来的には、メインモニターで全体確認、ペンタブで書き込み、別モニターで比較図面を見る等の複数画面運用を目指す。

## 6.4 OCR / 手書き文字認識
将来、PDF内文字取得、OCR、手書き文字認識、ペンタブによる文字入力補助等を検討する。

## 6.5 AIチェック
PDFから文字・注釈・図面情報を取得し、AIが確認を補助し、人間が最終確認する流れを検討する。

## 6.6 集計機能
PDFMarkupで付けた注釈情報を利用し、口径、工種、集計対象、延長、撤去、新設、その他業務情報を拾い上げられるようにする。

## 6.7 JSON生成
PDF注釈へ最低限の情報を残し、PDFを開いた際に必要なJSONデータを生成できる方式を将来候補として維持する。

基本思想：

> **PDFだけを残しても、必要な作業情報を再構築できる状態を目指す。**

## 6.8 プラグイン
将来、水道設計固有機能等を追加する場合、PDFMarkup本体へすべて直接組み込むのではなく、必要に応じてプラグイン化を検討する。

例：

```text
水道プラグイン
├─ 口径
├─ 延長集計
├─ 配管寸法
└─ 工種集計
```

# 7. 将来の大幅改修を避けるための設計方針

Ver1.51では将来機能をすべて作らない。ただし、将来追加する際に全面作り直しになる構造はできるだけ避ける。

## 7.1 描画設定はPreset化可能な構造を維持する
現在は朱書き・チェックを中心に設定する。将来、色別・用途別・ユーザー独自Preset・業務別Presetへ拡張できるようにする。

## 7.2 PDF注釈情報を失わない
将来の集計・JSON生成へ必要になる可能性がある、type、color、diameter、工種、集計対象等の情報を安易に削除しない。保存形式を変更する場合は互換性を確認する。

## 7.3 PDF標準との互換性を優先する
PDFMarkup独自形式だけで成立する設計へ過度に寄せない。可能な範囲でAcrobat、他PDFビューア、印刷、再保存との互換性を維持する。

## 7.4 複数PDF機能を将来のWorkspaceへつなげる
Ver1.51では複数ウィンドウと描画設定同期までとする。将来、PDF比較、ページグループ、複数モニター、ペンタブ、Workspaceへ発展できるよう、PDFごとの状態とアプリ共通状態を分けて扱う。

## 7.5 PDF処理と業務固有機能を密結合させすぎない
PDF表示・注釈・保存等の基盤部分と、水道、口径、工種、集計、AI、OCR等の業務機能を将来分離できる余地を残す。

Ver1.51で大規模分割は行わない。必要になった段階で分離する。

## 7.6 今使わない情報を勝手に削らない
現在UIで使用していない情報でも、将来仕様に必要になる可能性が明記されているものは、不要という理由だけで削除しない。

- 左下にフルパスを常時表示しない。
- チェック色16色を使い分けられる。
- 複数PDFで描画設定を共有できる。
- 必要なウィンドウだけ描画設定同期から外せる。
- PDF保存・再読込・注釈表示に大きな互換性問題がない。
- Ver1.51以降の将来目標を妨げる変更をしていない。

---

# 12. 最終目標

PDFMarkupは、

> **人間がPDF図面を確認し、朱書き・チェックを行うための実用品**

を第一段階とする。

その上で将来的に、

```text
PDFMarkup
 ↓
PDF図面チェック基盤
 ├─ 比較
 ├─ ページ / 束管理
 ├─ 複数モニター
 ├─ OCR
 ├─ AI
 ├─ 集計
 ├─ JSON
 └─ 業務別プラグイン
```

へ育てる。

Ver1.51では将来機能を急いで実装しない。

ただし、

> **将来必要になる情報や拡張余地を失わないこと**

を設計上の重要事項とする。

まずは実際に使えるPDFMarkupを少しずつ改善し、その利用結果と利用者の要望を次Versionへ反映していく。
